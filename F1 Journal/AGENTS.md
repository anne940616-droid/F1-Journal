# AGENTS.md｜F1 Journal 專案開發說明

## 1. 這個專案在做什麼
F1 Journal 是一個介紹 Formula 1（世界一級方程式賽車）的入門網站。我希望把平常需要分散查找的資訊，整理成容易瀏覽的內容，讓剛開始接觸 F1 的人也能認識這項運動。

目前先整理四類內容：
- 車隊（Teams）
- 車手（Drivers）
- 賽道（Circuits）
- F1 入門知識（F1 Guide）

這是個人學習專案，並非 F1、FIA 或任何車隊的官方網站。

## 2. 網站風格
- 整體方向是賽車雜誌風格，簡潔、有速度感，不要做成制式的企業網站。
- 主要使用黑、白、灰，紅色作為重點色。
- 標題可以醒目，但內文要容易閱讀。
- 卡片、按鈕、標題和間距盡量沿用現有設計。
- 手機也要能正常閱讀及操作。
- 不要為了增加視覺效果而塞入太多動畫、圖示或裝飾。

## 3. 使用的技術
本專案目前使用：
- HTML：網頁內容與區塊
- CSS：版面、顏色和手機版樣式
- JavaScript：讀取資料、顯示卡片及搜尋功能

目前不需要使用框架、資料庫或建置工具。除非我明確提出需求，否則不要自行增加套件或改變技術架構。網站需要能直接部署在 GitHub Pages。

## 4. 檔案放置方式
```text
f1-journal/
├── index.html       # 網站主要結構
├── AGENTS.md        # 本開發規則
├── README.md        # 專案介紹與操作方式
├── css/
│   └── style.css    # 所有視覺樣式
└── js/
    ├── data.js      # 車隊、車手、賽道及文章資料
    └── app.js       # 顯示資料與互動功能
```

請盡量在原本的檔案中修改，不要另外建立 `style-new.css`、`app-final.js` 這類重複檔案。

## 5. 新增資料時的格式
網站資料集中放在 `js/data.js`，不要把大量內容直接寫進 `app.js`。

### 新增車隊
每筆資料包含：
- `name`：車隊名稱
- `country`：國家
- `category`：類別
- `color`：代表色，使用 HEX 色碼
- `description`：簡短介紹

### 新增車手
每筆資料包含：
- `name`：姓名
- `number`：車號，使用字串
- `team`：所屬車隊
- `country`：國籍
- `note`：簡短介紹

### 新增賽道
每筆資料包含：
- `name`：賽道名稱
- `location`：所在地
- `character`：賽道特色，簡短描述即可

### 新增入門文章
每筆資料包含：
- `title`：文章標題
- `category`：主題分類
- `body`：一至三句的入門說明

新增資料時，請沿用原本欄位名稱和格式，不要自行更換命名方式。

## 6. AI 協作時請遵守的流程
收到新增或修改需求時，請依序進行：

1. 先閱讀本文件，確認專案原本的做法。
2. 判斷這次要修改的是資料、畫面還是互動功能。
3. 如果只是新增車手或車隊，優先只修改 `js/data.js`。
4. 如果需要新增畫面，先沿用現有卡片和排版，不要整個網站重做。
5. 修改完成後，列出改了哪些檔案，以及修改原因。
6. 檢查原本的搜尋、導覽和手機版是否仍能使用。
7. 如果無法實際執行測試，要清楚說明，不可以直接宣稱測試通過。

不要擅自刪除原有內容，也不要順手重寫與這次需求無關的程式。

## 7. 資料正確性與圖片
- 車手所屬車隊、車號、賽季陣容和規則可能隨年份改變，新增前要確認資料適用的年份。
- 優先參考 F1、FIA、車隊或賽道的官方資料。
- 不確定的數字或紀錄不要猜測；找不到可靠資料時，先標示待確認或不放入。
- 圖片使用前要確認有使用權，或使用自己提供、可合法使用的素材。
- 不要擅自使用官方標誌或讓網站看起來像官方產品。

## 8. 修改後的基本檢查
每次完成修改，至少確認：
- 首頁可以正常開啟。
- 四個內容區塊都有正確顯示。
- 車隊搜尋可以使用。
- 導覽連結可以跳到正確區塊。
- 手機畫面沒有明顯跑版或水平捲動。
- 新增資料沒有漏填欄位或重複項目。

## 9. 完成的標準
這次修改要符合原本的網站風格、資料格式和檔案分工，也不能讓既有功能失效。回覆時請簡單說明修改內容、測試結果，以及還有哪些地方需要我確認。
